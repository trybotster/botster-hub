## Product decision ledger

- Default: one Hub-owned `session_type` definition contract replaces the command-only `session_templates` vocabulary everywhere in this repository. There is no legacy alias, compatibility reader, parallel schema, or `v2` source name.
- Default: definition semantics are orthogonal data, not subclasses or Core enums. A definition keeps launch fields and adds presentation fields plus open, validated semantic descriptors: a namespaced role (with first-party `botster.agent` and `botster.accessory`), interaction intent, string traits/capabilities, and lifecycle intent. Long-running lifecycle intent never implies agent role, and interactive intent never implies either role or lifecycle.
- Default: source authority remains package < device < repo, with explicit request values limited to already-admitted launch overrides. Effective rows identify their winning provenance, editability, overridden candidates, and validation/conflict diagnostics.
- Default: device definitions are Hub-state CRUD; repo definitions are admitted-target-scoped CRUD through Hub filesystem policy; package definitions are read-only projections of enabled package manifests.
- Default: the canonical spawned-session family remains `session`; spawned-session classification is projected into its rows from opaque Core host metadata. Effective definitions use the separate Hub-owned entity family identifier `session_type`. It is a third canonical delivery lane, not a plugin provider: HubRuntime owns a durable monotonic definition generation, snapshots and mutation frames use that generation as `snapshot_seq`, and daemon subscriptions preserve the existing bounded delivery behavior (overflow marks the subscription for a full snapshot with `subscriber_overflow`; failed delivery disconnects it). The negotiated feature is `session_type_entity_subscriptions`.
- Default: this breaking request/response rename advances `PROTOCOL_VERSION` because request semantics change. The new required definition/session entity shapes and regenerated fixtures also advance `CONFORMANCE_FIXTURE_REVISION`, allocated at merge time strictly above every meaning on current `origin/main` and the newest published `@trybotster/hub-test-support`. `current_feature_list()` advertises the new entity feature, and stale clients fail compatibility negotiation before issuing a removed operation.
- Default: `session_type_entity_subscriptions` is deliberately **required**, not merely supported. Per [[adding a hub client feature constant is a three site change]], `DaemonCompatibilityRequirement::current()` derives `required_features` from `current_feature_list()`, so advertising the feature also makes it mandatory for every client at the new revision, and the third site is the published `botster-hub-test-support` support-matrix expectation enumerating it under both `required_features` and `supported_features`. That mandatory effect is intended cold-cut behavior: stale first-party clients must receive a typed compatibility failure rather than optional silent compatibility, and Web/TUI adoption stays with their registered tickets. Because this touches `current_feature_list()` and `CONFORMANCE_FIXTURE_REVISION`, the required gate is workspace-scoped bare `./test.sh`, not a target-scoped subset.
- Non-goal: client management UX, renderer-specific presentation, Project Pipelines workflow changes, new Core taxonomy, or a general filesystem abstraction.
- Ask-human threshold: only if implementation discovers a required closed vocabulary whose values materially change the product semantics. Field spelling and validation details may be settled within this ledger as long as the orthogonality and namespacing requirements remain true.

## Blocking dependency and ownership boundary

The Hub owns session-type vocabulary, source precedence, editability, filesystem/state mutation policy, metadata construction, client APIs, entity projection, diagnostics, and first-party definitions. `botster-hub-client` is an external DTO boundary, but its crate and generated TypeScript artifact are intentionally maintained in this repository and are part of this ticket.

Core owns only reusable persistence and transport of opaque host metadata. The locked Core already accepts `CoreSessionMetadata`, but `SessionLifecycleRecord` omits it, so a restarted Hub cannot rebuild authoritative `session` entity rows without duplicating authority. That prerequisite is registered as `ticket_1785970599_947769` on `botster-core` target `tgt_1f7bce66eb304881980f9b4a2a5ae3fe`, dependency `dependency_1785970611_682359`. It must expose the existing opaque map on lifecycle baseline/change records and prove worker-backed persistence/adoption/restart; it must not add role, interaction, trait, lifecycle, or session-type policy.

This run is full delivery, not a partial split. **Implement must not start until** `ticket_1785970599_947769` has completed, its Core change is merged, and a consumable revision has been identified. On resume, the first implementation action is to update `Cargo.lock` to that delivered Core revision and record the Core commit, Hub commit, worker binary realpath, and Hub binary realpath separately. If the dependency is still open or only has unmerged source, this run remains at Plan/blocked sequencing; no session-type CRUD or protocol half may ship without canonical session-row projection and acceptance checks 2 and 8.

No other cross-repository implementation is folded into this run. Botster Web, TUI, and Workspaces may consume the generated contract later; their UX or persistence changes require their own targeted tickets. Same-target sibling `ticket_1785970233_522967` also regenerates Hub client/test-support assets; whichever branch merges second must rebase its compatibility constants and generated package content rather than reuse the sibling's revision.

## Implementation plan

1. **Replace the definition model and sources cold turkey.** In `src/session_templates.rs`, replace command-only template/source structs and APIs with the single session-type contract. Preserve command, args, cwd policy, environment/override allowlist, context, and target admission. Add bounded presentation and semantic fields, validate ids/namespaced roles/traits independently, retain package < device < repo precedence, and return effective rows with exact source identity, editable operations, overrides, and diagnostics. Rename the repo file to `.botster/session-types.json` and the package manifest field to `session_types`; remove old names and readers in the same change.
2. **Make each source's authority executable.** In `src/persistence.rs` and `src/packages.rs`, persist device-owned definitions and read package-owned definitions under the new contract. Advance the Hub-state schema for the breaking durable field rename, preflight the root version before full decode, and separately test malformed JSON, old supported-shape/version rejection, and invalid current shape. Add narrowly scoped HubRuntime/HubClientApi mutations: full device create/update/delete, admitted-target repo create/update/delete using ordinary filesystem primitives and atomic writes, and typed read-only rejection for package rows. Reuse current spawn-target admission and path traversal policy; do not expose direct paths or raw state writes to callers.
3. **Expose one source-aware management protocol and declare the cold-cut compatibility boundary.** Replace session-template daemon/client/CLI/Lua names and DTOs in `src/client_api.rs`, `src/daemon_transport.rs`, `src/main.rs`, `src/lua_runtime.rs`, `src/lib.rs`, and `crates/botster-hub-client/src/lib.rs`. List/show/resolve/spawn continue over the new definition, while create/update/delete carry explicit source/target intent and return typed provenance/editability/diagnostic results. The CLI becomes `session-types ...`; the Lua worker capability remains Hub-authoritative and exposes only operations its granted package needs. Package definitions reject mutation rather than silently forking into device state. Advance `PROTOCOL_VERSION` for the breaking operation/DTO semantics; advance `CONFORMANCE_FIXTURE_REVISION` for the required entity/fixture shapes; add `FEATURE_SESSION_TYPE_ENTITY_SUBSCRIPTIONS = "session_type_entity_subscriptions"` to the public constant, `current_feature_list()`, generated TypeScript, and test-support feature matrices. Compatibility requirements must reject a stale version/revision with typed `DaemonCompatibilityError` before removed operations can be sent.
4. **Carry authoritative semantics into live sessions.** Materialization converts the selected definition's id, source, role, traits, interaction, and lifecycle intent into bounded, namespaced `CoreSessionMetadata` entries alongside the current plugin/client owner facts. Every ordinary, managed-worktree, CLI, daemon, and Lua spawn path must use the same metadata builder. Consume the dependency's lifecycle metadata projection in `src/daemon_transport.rs` so initial subscription, upsert/patch, natural exit, reconnect, and post-restart baselines produce the same typed fields on `DaemonSessionEntity`; missing metadata on genuinely untyped direct sessions is explicit absence, never inference from command, name, owner, or duration.
5. **Publish `session_type` mutation deltas on an explicit canonical lane without polling.** Add a Hub-owned `session_type` branch alongside the existing Core-backed `session` and plugin-provider branches in subscription registration/driving. HubRuntime persists a monotonic definition generation with the authoritative device definition state; package/repo reload compares the full effective/provenance map and advances that generation only for an observable change. Initial subscription and reconnect emit the full effective map at the current generation. Device/repo mutations compute before/after effective rows and emit ordered upsert/patch/remove frames at the new generation; losing lower-precedence edits still change and emit the affected provenance/diagnostic row. Each subscriber retains its last generation and row map. Queue overflow sets `subscriber_overflow` and retries a full current-generation snapshot; repeated full queues remain pending, serialization/frame-size errors return typed subscription errors, and disconnected senders are removed. This lane reuses `DaemonEntityFrame` and its bounded sender but never registers a fake plugin provider or rides the unrelated Core lifecycle cursor.
6. **Regenerate and migrate every first-party producer/consumer with collision-safe publication identity.** Immediately before allocating compatibility values, fetch/re-read current `origin/main`, inspect the newest published `@trybotster/hub-test-support` metadata and installed contract bytes, and account for sibling `ticket_1785970233_522967`. Choose `PROTOCOL_VERSION` above the merged request-semantic meaning and `CONFORMANCE_FIXTURE_REVISION` strictly above both the repository and every published meaning; never preserve a branch-local increment after convergence. Update `crates/botster-hub-client/src/typescript.rs` and regenerate `crates/botster-hub-client/generated/daemon-protocol.ts`. Migrate package manifests and fixture definitions, including `examples/project-pipelines/botster-package.json`, package contract-matrix copies, Hub client fixtures, and test-support assets. Keep the Project Pipelines Lua workflow behavior unchanged except for calling the renamed Hub capability/fields. 7. **Document the authoritative contract and operational path.** Update `README.md`, `docs/client-protocol.md`, `docs/lua-plugin-abi.md`, relevant fixture READMEs, and this plan if implementation proves a different boundary. ## Assumptions and unknowns

- Assumption: the cold cut intentionally rejects existing Hub state and old repo/package definition files rather than migrating or dual-reading them; the schema/version error must be accurate and actionable.
- Assumption: presentation fields are bounded scalar metadata (for example label/description/icon) and semantic descriptors are strings/string sets, allowing Hub validation without a Core enum. The implementer should keep the smallest field set that satisfies concrete first-party definitions.
- Assumption: `session_type` is a Hub product term, while `role`, `interaction`, `traits`, and `lifecycle` remain independent. No `AgentSession`/`AccessorySession` classes or inferred defaults are permitted.
- Assumption: repo CRUD writes only `<admitted target>/.botster/session-types.json`; symlink/traversal behavior must fail closed under the same canonical-root policy used for spawn admission.
- Resolved (Core merged as `33ebcd98d19031d23e91b03d8da0ee3f8d1410d4`, PR #117): the accessor is the public field `SessionLifecycleRecord.metadata: CoreSessionMetadata`, carried on both `SessionLifecycleBaseline.sessions` and `SessionLifecycleChangeKind::Upsert { record }`, persisted through `RegistryRecord.metadata` and restored on adoption. Hub consumes that map directly and adds no temporary cache. Because the field is `#[serde(default)]`, an absent map deserializes to an empty map: empty and absent are one state by design, so Hub must treat "no session-type metadata" as explicit absence and must not build a tri-state.
- Assumption: Plan approval does not authorize partial implementation while the registered Core dependency is open. The full run resumes only after a merged, consumable Core revision exists.
- Assumption: existing first-party Web/TUI/Workspaces binaries are stale by design during the cold cut. The protocol-version requirement turns that lag into an immediate typed compatibility rejection; their migration remains in their own tickets.
- Unknown until implementation: whether a lower-precedence definition mutation can be represented as a sparse patch or needs an effective-row upsert. The observable requirement is ordered `session_type` state at one Hub generation with override diagnostics, not a preferred frame variant.
- No convention conflict found. The cold cut, Hub authority, Core taxonomy boundary, entity-only state sync, framework/filesystem reuse, and real-runtime downstream proof all align with loaded guidance.

## Risks and mitigations

- **Split authority after restart:** in-memory Hub context would lose truth. Block on the Core lifecycle-metadata dependency and prove restart/reconnect from the real worker-backed daemon.
- **Semantic collapse:** mapping long-running to agent or interactive to accessory recreates subclasses implicitly. Use independent fields and fixtures covering interactive agent, interactive terminal accessory, and service accessory.
- **Precedence/editability confusion:** a mutation may succeed but remain overridden. Effective DTOs and frames must expose winning provenance and override diagnostics, and tests must cover all three sources.
- **Unsafe repo writes:** target-local management can escape through paths/symlinks or edit an unadmitted repo. Canonicalize against the admitted target, use atomic filesystem replacement, reject disabled/missing targets, and test negative paths.
- **Breaking durable state mislabeled corrupt:** preflight schema version before deserializing the new shape and test malformed/old/current failures independently.
- **Protocol drift:** required Rust fields can compile locally while generated TypeScript/test-support mirrors lag. Enforce generator and asset sync checks across the workspace and package contents.
- **Stale first-party clients pass negotiation:** removed operation names would otherwise fail as unknown requests. Bump the semantic protocol version, update advertised/required compatibility descriptors, and prove an old requirement receives typed `DaemonCompatibilityError` before request dispatch.
- **Concurrent fixture revision collision:** sibling `ticket_1785970233_522967` touches the same generated assets and can independently choose the same next revision for different bytes. Re-read merged source and published package at regeneration time, allocate above both, and bind the installed revision to exact installed protocol tokens/fixture bytes.
- **Unwired pushed state:** CRUD responses can pass while subscribers remain stale. Real socket tests must hold subscriptions open and assert exact snapshot/upsert/patch/remove convergence without a list refresh.
- **Stale Core/Hub binaries:** use fresh target paths and record Hub SHA, locked Core SHA, and both binary realpaths for restart proof.
- **Oversized or sensitive metadata:** keep Core metadata to small classification facts only; never include cwd, prompt, title, username, terminal content, or arbitrary presentation text if it can contain PII.
