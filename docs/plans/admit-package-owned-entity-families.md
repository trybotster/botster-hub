### Canonical package entity namespace v1

Define exactly one Hub helper, `package_entity_owner_token`, and route registration, surface admission, provider invocation, snapshot validation, and reconnect hydration through it. The v1 mapping is:

- Reserve the ASCII marker `bns1_` (`Botster namespace v1`). If a nonempty package ID contains no `.` and does not begin with `bns1_`, its owner token is the package ID unchanged. Therefore `project-pipelines` maps to `project-pipelines`, and its public families and bindings remain `project-pipelines.*` and `/project-pipelines.*`.
- Otherwise, the owner token is `bns1_` followed by the lowercase hexadecimal encoding of the package ID's exact UTF-8 bytes, with no Unicode normalization or delimiter substitution. Thus `botster.plugin-contract-matrix` maps to `bns1_626f74737465722e706c7567696e2d636f6e74726163742d6d6174726978`, and a fixture family such as `run` is protocol-visible as `bns1_626f74737465722e706c7567696e2d636f6e74726163742d6d6174726978.run` (binding path `/bns1_626f74737465722e706c7567696e2d636f6e74726163742d6d6174726978.run`).
- The inverse treats a token without `bns1_` as the identical package ID. A marked token's suffix must be even-length lowercase hex that decodes to valid UTF-8 and canonically re-encodes to the same token; the empty suffix canonically represents an empty manifest ID, while malformed or noncanonical marked tokens are rejected. Provider admission may separately reject an empty manifest ID if package policy already makes it invalid, but the namespace function remains total and reversible for every Rust/JSON package-name string.
- Collision argument: identity tokens never begin with the reserved marker, encoded tokens always do, and lowercase hex is injective over exact UTF-8 bytes. The ranges are disjoint, and two distinct package IDs cannot produce the same encoded token. A single-segment package ID that itself begins with `bns1_` uses the encoded branch; this reserved-marker escape is required because preserving every possible single-segment string while also placing encoded dotted IDs in the same single-segment codomain is not collision-free.

The package manifest name remains the package's registry/lifecycle identity. Only its entity owner token and the resulting entity-family/binding strings use this mapping. Package authors declare the resulting exact protocol-visible family in the provider descriptor, frames, and UiNode paths; Hub recomputes the expected token from the authoritative manifest name and rejects any other prefix.

## Assumptions and unknowns

- Assumption: one descriptor per exact family, with `descriptor_id` equal to the declared entity type, is the smallest auditable ABI. If repository precedent demands a different explicit descriptor body, preserve exact-family identity and Core ownership validation rather than adding implicit discovery.
- Assumption: provider hydration is query-on-subscribe/reconnect; live mutation fanout is not required by this ticket beyond any explicitly returned validated frames. Do not invent a broadcast subsystem without evidence that the acceptance path requires it.
- Assumption: only a whole-family snapshot can establish reconnect authority. Upserts alone must not count as a baseline.
- Resolved namespace policy: `package_entity_owner_token` uses the exact `bns1_`/lowercase-UTF-8-hex algorithm above. It is identity-preserving for ordinary unreserved single-segment IDs, including `project-pipelines`; marker-prefixed single-segment IDs use the encoded branch so the mapping remains injective. Exact UTF-8 bytes are package identity—do not normalize Unicode.
- Unknown to resolve during implementation: the narrowest source-compatible Rust representation for generic plugin rows in `DaemonEntityFrame`. Prefer a shared generic record value plus typed session conversion over parallel wire variants or duplicated contracts.
- Resolved bound policy: provider dispatch must reuse `PLUGIN_EVENT_TIMEOUT_MS = 1_000` from `src/runtime.rs`, the existing Hub plugin-worker dispatch bound, rather than the unrelated 30-second session-template spawn timeout or a new provider-specific setting. A durable-store snapshot that does not finish within one second fails with the existing typed worker timeout; changing that product bound is outside this surgical ticket. Preserve `ENTITY_SUBSCRIPTION_QUEUE_CAPACITY = 64` and `DAEMON_MAX_FRAME_BYTES = 1 MiB` from `src/daemon_transport.rs`; validate and serialize provider output before enqueue and reject an oversize frame with a typed provider error. The production WebRTC adapter preserves `LOCAL_WEBRTC_CHUNK_PAYLOAD_BYTES = 12 KiB` in `src/local_webrtc.rs` and the `LOCAL_WEBRTC_MAX_DELIVERY_BYTES = 16 MiB` ceiling owned by `crates/botster-hub-client/src/lib.rs`; the stricter shared 1 MiB daemon entity-frame bound applies before either socket or WebRTC delivery.
- Resolved unload policy: disabling, reloading away, or unloading the owning provider removes its descriptor/resource and terminates active subscriptions for that family through the existing connection cleanup path. A subsequent subscription fails with a typed provider-unavailable/undeclared-family response instead of replaying cached rows.

## Risks

- A prefix or normalization mistake could let one package bind or hydrate another package's records; compare exact Core entity type and owner, not string prefix alone.
- A lossy delimiter replacement or ambiguous escape can collide dotted, underscore-like, marker-like, or Unicode package IDs. Use the tagged exact-byte encoder, canonical inverse, and one shared helper; never normalize Unicode or hand-build mapped strings at call sites.
- Broadening the DTO to raw JSON without producer validation could move trust into Web/TUI. Hub must validate owner, exact family, record shape/id, snapshot authority, and sequence before delivery.
- Reusing the session reconciliation state machine for plugin providers could accidentally make plugin data dependent on Core lifecycle drains. Keep session authority and provider query lifecycle distinct behind the shared frame envelope.
- Invoking Lua providers on the daemon control path can block unrelated clients or make large durable snapshots fail under the existing one-second dispatch bound. Invocation must stay inside the existing plugin worker boundary, reuse `PLUGIN_EVENT_TIMEOUT_MS`, retain current bounded queues, and return the typed worker timeout rather than extending or bypassing the bound.
- Reconnect could replay stale in-memory rows instead of consulting durable plugin authority. The test must mutate provider-backed state between connections and prove the second baseline reflects the new value.
- Package disable/reload/unload can leave descriptors, resources, or subscriptions alive. Require negative lookup after disable/unload and observable subscription cleanup.
- Generated TypeScript/test-support drift can make Rust pass while Web/TUI consume a stale shape. Asset synchronization and generated-contract tests are mandatory.
